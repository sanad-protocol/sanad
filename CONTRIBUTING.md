# Contributing

Everyone may comment, propose changes and implement the specification. No membership is needed.

## Proposals

Open an issue that names the section and the rule and states the change you propose and why. A comment period of 14 days applies before a decision. Decisions are recorded with their reasons. A change that alters the expected result of any conformance vector requires a new minor version of the specification.

## Pull requests

- Keep a change small and focused; explain it in the description.
- Run `node build.mjs && node test.mjs` before you submit.
- Page texts: English is authoritative. Translations are drafts until a native speaker has reviewed them; say so in the pull request.
- Write in plain, neutral prose. State only what is true today.

## Sign-off (Developer Certificate of Origin)

Every commit must carry a line `Signed-off-by: Your Name <your.address@example.org>` (use `git commit -s`). By adding it you confirm the Developer Certificate of Origin, version 1.1 (<https://developercertificate.org/>): that you wrote the contribution or have the right to submit it under the licence of the file.

## Licences of contributions

Contributions to the specification text are made under the specification licence (CC BY 4.0). Code contributions are made under Apache-2.0.

## Conduct

See `CODE_OF_CONDUCT.md`. Reports go to the contact address in `SECURITY.md`.
